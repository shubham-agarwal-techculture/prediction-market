# Prediction Market Application with Django

Build a Django-based prediction market application where users predict on various randomly-behaving entities (sports, financial, random events) and earn points for correct predictions.

## Summary
Build a Django-based prediction market application with OAuth authentication, SQLite database, and background tasks for generating random outcomes. Users can predict on multiple categories (sports, financial, random events) and earn points for correct predictions.

## Implementation Steps

### 1. Project Setup and Dependencies
- Initialize Django project with app structure
- Install required packages:
  - Django
  - Django REST Framework (for API endpoints)
  - Celery + Redis (for background tasks)
  - django-allauth (for OAuth integration)
  - sqlite3 (built-in)
- Configure Django settings with SQLite database
- Set up virtual environment

### 2. Database Models
Create the following models in Django:
- **User**: Extend Django's User model with score and profile info
- **Category**: Prediction categories (Sports, Financial, Random, Custom)
- **Event**: Represents a prediction event with:
  - Category (ForeignKey)
  - Title/description
  - Event type (match, price movement, random, etc.)
  - Start time and end time
  - Status (pending, active, resolved, cancelled)
  - Actual outcome (null until resolved)
- **Prediction**: User predictions with:
  - User (ForeignKey)
  - Event (ForeignKey)
  - Predicted outcome
  - Timestamp
  - Status (pending, correct, incorrect)
- **Entity**: Represents the randomly-behaving entities with:
  - Name
  - Type (team, stock, random generator, etc.)
  - Current state/value
  - Category (ForeignKey)

### 3. OAuth Authentication
- Configure django-allauth for OAuth providers (Google, GitHub)
- Set up social authentication views
- Create user registration/login pages
- Add user profile page showing score and prediction history
- Configure authentication middleware

### 4. Prediction API Endpoints
Create REST API endpoints using Django REST Framework:
- `GET /api/categories/` - List all categories
- `GET /api/events/` - List active events
- `GET /api/events/<id>/` - Get event details
- `POST /api/predictions/` - Create a prediction
- `GET /api/predictions/` - List user's predictions
- `GET /api/user/score/` - Get user's current score
- `GET /api/leaderboard/` - Get top users by score

### 5. Background Task System
- Set up Celery with Redis for background tasks
- Create Celery tasks for:
  - Generate random outcomes for random events
  - Simulate sports match results based on random algorithms
  - Simulate financial market movements
  - Resolve events when their end time is reached
  - Update user scores based on prediction results
- Configure Celery beat for scheduled tasks

### 6. Random Entity Behavior Logic
Implement random behavior generators:
- **Sports events**: Random winner based on team "strength" + randomness
- **Financial events**: Random price movements with trend bias
- **Random events**: Coin flips, dice rolls, etc.
- **Custom events**: Configurable random behavior
- Entity state updates via background tasks

### 7. Frontend Interface
Create a simple frontend using Django templates:
- Home page showing active events by category
- Event detail page with prediction form
- User dashboard showing:
  - Current score
  - Prediction history
  - Win rate statistics
- Leaderboard page
- OAuth login/logout buttons
- Real-time event status updates (optional: WebSocket/Django Channels)

### 8. Event Resolution and Scoring
- Implement event resolution logic in Celery tasks
- Compare predicted outcomes with actual outcomes
- Update user scores:
  - Correct prediction: +points
  - Incorrect prediction: -points or 0
- Mark predictions as correct/incorrect
- Update event status to "resolved"

### 9. Admin Interface
- Use Django admin for:
  - Managing categories
  - Creating/editing events
  - Viewing all predictions
  - Managing users
  - Manually resolving events if needed

### 10. Testing and Validation
- Write unit tests for:
  - Model validation
  - Prediction logic
  - Scoring calculations
  - API endpoints
- Test background task execution
- Test OAuth authentication flow
- Verify event resolution and scoring

## Risks/Considerations
- **Celery/Redis setup**: Requires Redis server running - may need local installation or Docker
- **OAuth setup**: Requires API keys from providers (Google, GitHub) - user must provide these
- **Randomness quality**: For financial simulations, random behavior won't reflect real markets
- **Event timing**: Background tasks need to handle timezone and scheduling correctly
- **Scalability**: SQLite is fine for development but may need PostgreSQL for production
- **Real-time updates**: Without WebSockets, users need to refresh to see resolved events
